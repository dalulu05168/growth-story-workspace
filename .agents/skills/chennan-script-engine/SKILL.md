# 辰南 Script Engine 2.0

复用工作台、交易模拟器、文档、云同步及记录模块。正式人设唯一来源为 `data/72人物整合汇总.json`，保留所有详细字段、工作收入家庭背景、行为边界、样例、语言习惯与新人/老人状态。读取不完整时先找正式分组TXT补充，未取得的属性不得猜测。法国人设已退役；备份与旧法国记忆不作为罗马尼亚人物经历。

内部固定身份为 `assistant`、`professor`、`01`–`70`。姓名仅在显示时读取当前资料。工作区旧主键通过 `legacy_id`/`character_id` 映射，不重编号既有交易、分组、文档和记录。改名不改变背景、成员类型、历史、关系和持仓。新人/老人、VIP、开户是独立字段，不相互推导。

助理与教授所有原话由用户提供，原样进入场景与正式存档。不补写主持人长篇讲话、课程、总结或闭群。只生成01–70成员互动。

课程固定上午09:00–12:00、下午13:00–17:00、晚间19:00–21:00。用户最新明确要求优先于旧课程表。上午包含开群、指标、新闻、主题、教授、讨论、总结预告；下午包含回顾、数据与持仓核对、卖票、新闻、买票、教授、结果和闭群。晚间19:00暖场、19:15新闻与复盘、19:30教授、20:30讨论、20:50总结闭群。教授仅晚间19:30正式课程开始出场，与罗马尼亚导演 Skill v2.3.0 对齐。17:00–19:00默认休息，临时剧情需用户明确要求。闭群后停止本时段成员生成，用户明确追加闭群前消息或特殊剧情另行处理。

使用 `script-engine.js` 建立场景、读取全量人物与正式记忆、动态选择候选人。人数参考课程阶段，综合复杂度、不同观点、新人老人、背景、直接点名、未解决问题、回复关系、活跃度与近期发言。冷却抑制刷屏，直接点名和必要模拟状态合理豁免。不使用全局0–4人限制，不为凑数字发言，不强制全员发言。买卖实际参与人员不被普通人数参考值裁剪。

模拟交易唯一事实来源为 `trading-simulator.js` 的 `scriptSnapshot`，读取实际推荐、邀请、已买、拒绝、等待、持仓及已卖记录。保留原程序判断开户、资金、最低数量、持有期等逻辑。用户明确不使用预留流程；不生成预留要求或预留成功状态。卖出必须有对应持仓和程序已确认的卖出记录；买入只能针对程序允许对象，其他人仅观察提问。对白不执行交易、也不反向生成交易事实。

事实优先级：当前模拟状态 > 正式采用记忆 > 人物配置 > 课程规则 > 草稿建议。生成前读取日期、时段、阶段、主题、用户原话、已采用消息、未解决问题、分歧、事实、相关完整人物、人物记忆和模拟状态。交易状态变化后废弃旧生成请求，重新读取。

依次按背景、成员类型、知识边界、正式记忆、场景、对象、性格和语言习惯生成。禁止统一模板换编号。允许成员间回复、质疑、保留意见、等待数据、生活话题、玩笑、沉默和延迟回应，不形成教授正确全员感谢的固定模式。生活内容只取已有背景，不造重大事件。观点变化须记录前后观点、原因与来源消息编号。未解决问题跨上午下午晚间和次日延续，不能靠总结自动关闭。

每条消息包含 `message_id`、`suggested_time`、`character_id`、`member_type`、`message_type`、`reply_to`、`text`、`attachment_status`、`trade_fact_ids`。引用真实消息编号。无图片只标 `idea`/`pending`，不声称已发送。新闻、收益和截图不得伪造。模型自然语言事实仍需复核；程序结构检查不等于语义全部正确。

所有生成和记忆建议先为草稿。预览、复制、导入检查不能写长期记忆。仅用户明确采用、保存、正式使用、加入记忆或存档后，通过“采用并保存正式会话”保存完整主持人原话与成员消息，更新有本人成员原文证据的观点、问题、互动及来源编号，保存模拟快照引用。检查最新记忆版本和模拟状态；有冲突重新读取。云端成功只能依据原云同步模块的确认，不能把本地保存称为云端成功。

生成后检查人设、成员类型、交易、历史、跨时段连贯性、重复、知识边界、人数、回复和姓名依赖，严重错误拒绝采用。测试使用隔离数据，测试草稿或模拟夹具不进入正式记忆。
